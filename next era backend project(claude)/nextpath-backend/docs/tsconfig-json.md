# `tsconfig.json`

Standard Next.js TypeScript configuration, largely as generated by `create-next-app`, with strict type-checking turned on.

## Notable options
- **`"strict": true`** — enables all of TypeScript's strict type-checking flags (no implicit `any`, strict null checks, etc.). This is why the eligibility engine's optional fields (`profile.gpa?`, etc.) have to be handled explicitly rather than assumed present.
- **`"moduleResolution": "bundler"`** with **`"module": "esnext"`** — the resolution strategy Next.js expects for its bundler-based tooling (Turbopack/webpack), rather than Node's classic resolution.
- **`"jsx": "react-jsx"`** — the new JSX transform; components don't need to import React just to use JSX.
- **`"paths": { "@/*": ["./src/*"] }`** — the `@/...` import alias used throughout the codebase (e.g. `@/lib/eligibility/evaluate`). This alias is a TypeScript/bundler concept only — it's why `tsc --noEmit` resolved it fine but Vitest needed its own separate alias config (see `docs/vitest-config.md`).
- **`"plugins": [{ "name": "next" }]`** — enables Next.js's TypeScript plugin (adds awareness of Next-specific types like route handler signatures).
- **`"include"`** — covers `src/**/*.ts(x)` plus Next's auto-generated type files (`next-env.d.ts`, `.next/types/**/*.ts`, `.next/dev/types/**/*.ts`), which are regenerated automatically by `next dev`/`next build` and don't need to be committed.
- **`"exclude": ["node_modules"]`** — the only exclusion; test files are intentionally *not* excluded so `tsc --noEmit` also type-checks `*.test.ts` files.
